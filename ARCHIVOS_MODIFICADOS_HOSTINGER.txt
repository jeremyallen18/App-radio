ARCHIVOS MODIFICADOS PARA SUBIR A HOSTINGER
=============================================
Última actualización: vínculo real entre Programas y Equipo (locutores),
más la corrección previa de sincronización de horarios de programación
entre el panel de administración, la API (hive-backend) y la página
pública (RADIODOLIV_PAGINA).

------------------------------------------------
1) BASE DE DATOS (hive_db) — ejecutar UNA sola vez
------------------------------------------------
Solo si la base de datos en Hostinger ya existe (instalación previa).
Ejecuta este script SQL una sola vez contra la base compartida "hive_db"
(por phpMyAdmin o el cliente MySQL de Hostinger):

App-radio/hive-backend/migrations/034_radio_program_host_team.sql

Qué hace: agrega la columna "host_team_id" a la tabla "radio_programs"
(con su llave foránea a "radio_team"), necesaria para vincular un
programa con un integrante real del equipo.

Si vas a instalar la base de datos DESDE CERO (servidor nuevo), no
ejecutes la migración: usa directamente el archivo completo y ya
actualizado:

App-radio/hive-backend/schema.sql

(El archivo espejo RADIODOLIV_PAGINA/config/migrations/2026_09_11_add_program_host_team.sql
documenta el mismo cambio del lado de la página web, pero apunta a la
misma base de datos compartida: NO se ejecuta dos veces.)

NOTAS
------------------------------------------------
- Orden recomendado para aplicar esta actualización en Hostinger:
  1. Ejecuta el SQL de la sección 1 (solo una vez).
  2. Sube los archivos de la sección 2 (API) por FTP/cPanel.
  3. Sube los archivos de la sección 3 (página pública) por FTP/cPanel.
  4. Compila y publica la app Flutter con los archivos de la sección 4.
- Antes de subir, haz respaldo de los archivos actuales en el
  servidor (site_content.php, index.php, index.js, programas.js) y
  respaldo/export de la base de datos antes de correr el SQL.
- Si algo falla al ejecutar el SQL porque la columna ya existe, es que
  la migración ya se aplicó antes; puedes ignorarla con seguridad.
